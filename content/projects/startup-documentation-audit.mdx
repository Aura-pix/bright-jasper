## Current state

Nexus 9's FAQ covers basic questions adequately. A separate Help & Guide section already exists with useful topics, but it sits in an accordion format and requires authentication to view. Users who hit friction before logging in, or early in onboarding, have no self-serve option and have to contact support directly.

## The opportunity

The existing Help & Guide content doesn't need to be rebuilt from scratch. It needs to be made public and restructured into individual, task-based pages. The FAQ stays as-is for quick answers. An academic content section (blog, exam strategy) is a natural next step once the core guides are in place.

## Recommendation

### 1. Make guides fully public

Remove the authentication requirement from the current Help & Guide content and host it at a clean public route: `/guides`.

### 2. Restructure the format

Move away from the accordion/drop-down style. Replace it with:

- An index page (`/guides`) listing every available guide.
- Individual pages for each major topic — `/guides/getting-started`, `/guides/uploading-materials`, `/guides/quizzes-and-practice`, and similar.
- A consistent format per page: short intro, numbered steps, tips, and screenshots where they help.

### 3. Keep the existing FAQ

Leave the FAQ on the landing page for quick answers, and cross-link it with the new Guides section so users can move between the two.

### 4. Priority order

1. Core guides — Getting Started, Uploading, Quizzes, Payments, Troubleshooting.
2. Representative support materials.
3. Academic content and blog, later.

## Expected benefits

- Better onboarding, with fewer users dropping off before they get past initial setup.
- Lower support ticket volume, since common pre-login and early-onboarding questions get answered without a support request.
- Improved trust and SEO, since public documentation is indexable and signals a maintained product.
- A cleaner, more scalable documentation foundation to build the academic content section on top of later.
